# 검증 방향과 종료 기준

## 무엇을 결론 낼 것인가

첫 질문은 **현재 고정 모델이 단순 반전 팩터보다 상대적으로 더 잘 고르는가**다.
그 다음 질문은 **그 차이가 비용 후 수익과 실제 거래 환경에서도 남는가**다.
첫 질문의 성공을 두 번째 질문의 성공으로 바꾸어 말하지 않는다.

확실한 결론은 반드시 긍정적인 결론을 뜻하지 않는다. 신뢰구간이 0을 포함하면
현재 자료로 판단하기 어렵다는 결론을 낸다. 좋은 숫자가 나올 때까지 같은 실험을
연장하거나, 누락된 회차를 다른 회차로 대체하지 않는다.

## 1단계: 현재 고정 실험

- 대상: 이미 등록한 6h 모델, 예정 회차 60개. 모델·피처·선정·평가 규칙 변경 금지.
- 평가 단위: 코인 300건이 아닌 6시간 묶음 60회.
- 비교: 모델 SHORT 5개, 4h 반전 팩터 SHORT 5개, 동일 종목군 전체 SHORT.
- 원시 가격, 비용 가정, 누락 처리와 불확실성 계산은 기존 실험 규약을 따른다.
- 최종 검토는 모든 회차 처리가 끝난 후 한 번만 한다. 해결되지 않은 가격 문제가
  남아도 마지막 예정 신호의 진입+6h+48h 이후에는 자료 부족으로 종료한다.
- 중간 평균, IC, 게이트별 결과는 탐색용이며 모델 승격에 사용하지 않는다.

첫 신호 전에 별도로 저장하는 `output/experiment_supervision/review_plan.json`은
기존 원장의 protocol SHA-256에 연결된다. 원래 프로토콜을 고치지 않는다.

## 결론 분기

| 조건 | 결론 | 다음 단계 |
| --- | --- | --- |
| 60회 모두 유효, 모델-반전 차이의 95% 하한 > 0 | 해당 실험에서 상대적 개선 근거 | 거래소 가격·운영 정책 검증 설계 |
| 60회 모두 유효, 95% 상한 < 0 | 해당 실험에서 반전 기준선이 우세 | 모델 실패 원인 감사, 기준선 유지 비교 |
| 60회 모두 유효, 구간이 0 포함 | 효과 판단 보류 | 별도 표본 설계 후 후속 실험 사전등록 |
| 회차·가격 누락 또는 기한까지 미해결 | 자료 부족 | 수집·평가 운영 문제부터 복구 |
| 모델·코드·원장 무결성 실패 | 성과 해석 불가 | 무결성 원인 조사, 기존 증거 보존 |

모델의 비용 후 평균이 양수인지는 별도 기술 통계로 표시한다. 상대적 개선이
확인돼도 절대 손실일 수 있다. 어느 분기에서도 자동 주문·모델 교체·LONG 해제는 없다.

## 2단계: 실사용 차이 검증 설계

아래는 후속 단계의 설계이며 **현재 실행 중인 실험이 아니다**.

1. Bitget 종목 매핑, 실제 관측 시각, bid/ask와 가격 신선도를 독립적으로 저장한다.
   나중에 가져온 시세를 추천 당시 시세로 간주하지 않는다.
2. 동일한 미래 평가 구간에서 Upbit 대리 가격과 Bitget 가격의 차이를 비교한다.
   호가·펀딩 자료가 없으면 이를 실제 체결 수익으로 표현하지 않는다.
3. 순위 모델 자체의 효과와 운영 버퍼·게이트 효과를 분리한다. 같은 모델·같은
   종목군·같은 가격·같은 비용 조건에서 정책만 달리한 관찰군을 사전등록한다.
4. 긍정적인 하위 그룹을 사후 선택해서 전체 성공으로 보고하지 않는다. 표본 수,
   주요 지표, 최소 실용 효과, 비용 및 종료 조건을 후속 데이터 수집 전에 고정한다.

모델 학습을 다시 강화하는 것은 데이터 및 정책 문제와 분리된 다음 결정이다.
현재 모델에 상대적 효과가 있다는 근거 없이 복잡한 모델부터 추가하지 않는다.
효과가 불확실하면 분산·검정력 분석으로 후속 표본을 설계하되, 같은 원장을 이어서
유의성이 나올 때까지 반복 검정하지 않는다.

2026-09-30 실행 기록: [60회 사후 분석](completed_trial_analysis.md)으로 영향도·국면별
표본 불균형·필요 표본의 민감도를 계산했다. [후속 전환 후보](rotation_followup.md)는
주간 확인·냉각·비중·비용 함수를 테스트했으며, 84일 실행 가능성 파일럿을 설계했다.
초기에는 설계까지만 있었으나 후속 구현에서 별도 파일럿 원장·기한 내 비중 저장·정산·
복원·자동 종료를 기존 10분 점검 서비스에 연결했다. 실제 등록과 진행 상태는 별도
파일럿 규약·대시보드로 확인한다. 84일을 수익 우위 보장 기간으로 삼지 않으며, 과거
고정 모델 비교와 새로운 적응형 정책 비교의 검정력을 혼동하지 않는다.

## 자동 운영

- `xsec-experiment-supervisor.timer`: 독립 사용자 systemd 타이머, 10분 간격.
- 정상 분석 서비스와 독립적으로 누락 회차 및 이미 저장된 예측의 만기를 점검한다.
  새 추천 생성이나 텔레그램 발송은 하지 않는다.
- GitHub에는 상태 변화가 있을 때, 또는 최소 1시간 간격으로 요약을 발행한다.
  발행 실패는 다음 주기에 다시 시도한다. 전송·네트워크 장애 중 반영은 보장하지 않는다.
- 현재 상태: `output/experiment_supervision/status.json`.
- 최종 보고: `output/experiment_supervision/final_review.json`. 처음 확정한 보고서는
  나중 실행에서 덮어쓰지 않는다. 후속 실험을 자동 생성하거나 기존 실험을 재설정하지 않는다.
- 이 자동 운영은 정해진 검사와 보고를 수행하는 프로그램이다. 대화가 닫힌 뒤
  AI가 새로운 전략을 자율적으로 연구·수정하는 기능은 아니다.

설치 후 상태 확인 명령:

```bash
systemctl --user status xsec-experiment-supervisor.timer --no-pager
systemctl --user show xsec-experiment-supervisor.service -p Result -p ExecMainExitTimestamp
python scripts/supervise_experiment.py --no-publish
```

`--register`는 첫 예정 신호 이전의 최초 등록에만 쓴다. 이미 등록된 규약은
덮어쓰지 않는다. 재설치는 `bash deploy/install_experiment_supervisor.sh`이며 sudo는
필요하지 않다. 타이머의 정시 실행에는 수초의 systemd 오차가 있을 수 있다.

## 증거 보존

SQLite Online Backup API로 원장의 일관된 사본을 만든다. 같은 묶음에 고정 모델,
등록 당시 소스, 검토 규약 및 최종 보고를 포함하고 파일별 SHA-256을 검증한다.
검증된 묶음은 `output/prospective_backups/`에 저장한다. 내용이 같으면 중복 저장하지 않는다.
2026-09-30 운영자 선택으로 별도 디스크는 필수가 아닌 선택 사항으로 변경했다.
`--secondary-backup PATH`를 명시할 때만 다른 파일시스템에도 복사한다.

사본 묶음을 작업 디스크의 임시 폴더에 전체 복원한 뒤 원장 무결성·행 수·모델·소스
해시를 다시 검사한다. 운영 원장 위로 자동 복원하지 않는다. 사용 중인 백업 경로에
최소 5GiB 공간을 남기며, 부족하면 오류를 기록한다. 별도 국면 관찰 원장은
`output/regime_backups/`에 SQLite 사본·무결성·복원 검증을 별도로 수행한다.
기본 동일 디스크 사본은 파일 손상·실수 복구용이며 디스크 자체 고장 또는 호스트 전체
손실을 보호하지 않는다. 과거 별도 디스크 사본과 최종 보고의 오류 기록은 수정하지 않는다.

근거: [SQLite Online Backup API](https://www.sqlite.org/backup.html)는 가동 중 원장을
일관된 스냅샷으로 복사하는 공식 API다. 단순 파일 복사로 가동 중 DB를 백업하지 않는다.

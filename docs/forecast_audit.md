# 저장 예측 자동 성적표와 거래소 호가 관찰

2026-09-30. 원본 기록만 연결했던 [FREEZE 진단](ic_incident_20260930.md)의 후속 구현이다.
순위 예측을 다시 만들지 않고 저장된 점수를 자동 평가한다. 별도 진단 원장이며
기존 IC 이력·추천 게이트·모델·60회 종료 실험·336회 파일럿을 변경하지 않는다.

## 실제 등록과 확인

- 등록: **2026-09-30 16:15:24 KST**. 첫 신호 **9월 30일 20:00 KST**.
- 규약 SHA-256: `08814bbf342a17496fda5f1e32dce5cc726194b3088525c803a79dd68a8e3777`.
- 최초 동일 디스크 복원 checkpoint: `147cb8e2fbabe61eb248fe42ec0541479dc63810aa684b9f37cdfb2f71228169`.
  등록 직후 실제 신호·성과·호가 기록은 모두 0건이다.
- Bitget 공개 API 연결 점검: 804개 응답, BTC·ETH·XRP 3개 호가 신선도 통과.
  점검 시세는 실험 원장에 넣지 않았다. 현재 운영 100종목 중 매핑 93개·중복 0개도 읽기 확인했다.
- 실제 감독 서비스는 초기 게시 실패를 조사·수정한 뒤 **16:18:46 KST 정상 종료**했다.
  원격은 정상적으로 한 커밋 전진했지만 얕은 캐시 참조 갱신이 거부됐다.
  로컬 원격 추적 참조만 갱신하고 원격 업로드는 강제 푸시 없이 유지하도록 수정했다.
  실패·복구는 기존 운영 알림에도 기록됐으며 투자 추천 테스트 메시지는 보내지 않았다.

## 원본 채점

- `scripts/audit_forecasts.py --register`는 다음 미래 정기 신호부터 평가를 시작한다.
  이미 존재하는 원장을 재등록하거나 과거 CSV를 미래 관찰로 편입하지 않는다.
- UTC 05/11/17/23시 신호마다, 실제 기록 시각이 신호부터 45분 이내인 원본만 허용한다.
  첫 점검에서 발견한 적격 원본을 기록 시각·해시 순으로 선택하고 이후 교체하지 않는다.
- 원본 전체 종목·반올림 전 점수·결측 입력·모델 및 소스 해시를 원장에 복사한다.
  종목을 줄이거나 점수를 재계산하지 않는다. 늦은 기록만 있으면 신호 누락이다.
- 신호 +1h / +7h의 정확한 Upbit 원시 시가로 수익률을 계산한다. 마지막 봉 완료인
  +8h부터 채점하며, 실제 데이터 수집이 늦으면 가격을 기다린다.
- 모든 종목의 두 가격이 양수·유한·유일해야 한다. 누락·중복을 채우거나 제외하지 않는다.
  +55h까지 평가하지 못하면 실패로 고정한다. 지나서 가격이 생겨도 성공으로 바꾸지 않는다.
- Spearman IC를 계산한다. 상수 순위는 0점이 아니라 평가 불가다. 이는 IC 진단이며
  누적 수익·실제 계좌 손익·수익 우위 검정이 아니다. 완결 표본 평균에는 선택 편향과
  모델 버전 혼합 가능성이 있으므로 예정·누락·실패·평가 수를 함께 표시한다.

## 기존 IC와 대조

기존 `absolute_open_lag1_anchors_v1` 이력을 읽기만 한다. 원본 IC와의 절대 차이
0.03 이상을 진단 경고로 표시한다. 이는 유의성 기준이나 신규 매매 게이트가 아니다.

평가 때 저장한 재계산 원본도 있으면 모델 해시·종목군·점수 순위·타겟 차이를 검사한다.
같은 종목군일 때는 재계산 점수를 동일 원시 가격으로 다시 채점해 예측 차이와 타겟
차이를 구분할 단서를 남긴다. 숫자·종목 수가 기존 이력과 일치하지 않는 평가 원본을
그 이력의 확정적인 생성 근거라고 하지 않는다. 새 평가 원본이나 이력 변경도 이전
비교를 지우지 않고 별도 행으로 남긴다.

## 첫 실행과 Telegram 확인

정상 추천 보고서에 `score_evidence_sha256`와 당시 거래가능 종목 매핑을 추가한다.
메시지 형식·선정·전송 순서는 바꾸지 않는다. 같은 신호·원본 해시를 가진 보고서에
Telegram API의 `sent` 및 수신 확인 시각이 있을 때만 연결 확인으로 표시한다.
이는 사용자가 메시지를 읽었다는 증거가 아니다. 전송 실패와 이후 재시도 성공도
같은 원장에서 구분하며, 원본 기록 실패가 정상 코인 보고를 막지 않는다.

## Bitget 관찰

실사용 차이 검증의 **자료 수집·비교 경로**를 구현한 것이며 실제 체결 검증 완료가 아니다.

1. 신호 +45분 이내에 감독 서비스가 해시로 연결된 보고서를 발견해야 한다.
   해당 시점의 Bitget 매핑, 모델 점수 하위 5개, 운영 선택 5개, actionable 수를 고정한다.
   늦은 발견이나 불충분한 매핑은 관찰 실패다. 바스켓이 동일 종목군 밖이면 선택 비교를 하지 않는다.
2. 감독 서비스가 진입·종료 정시부터 5분 이내에 공개 ticker를 한 번 관찰한다.
   `bidPr/askPr`, 크기, 거래소 `ts`, 실제 수신 시각을 함께 보존한다. 시세 나이 60초 초과,
   미래 5초 초과, 역전 호가, 비양수 가격·크기, 중복·누락은 실패다.
3. 해당 관찰 창을 놓치면 현재 시세나 과거 캔들로 호가를 복원하지 않는다.
   수집 실패는 원장에 보존하며 다른 원본 IC 평가와 정기 Telegram 전송을 막지 않는다.
4. 동일 고정 종목군의 midpoint 수익으로 Bitget IC와 Upbit IC를 비교한다.
   양 시장의 통화·상품·수신 시각이 다르므로 차이를 순수 거래소 효과라고 하지 않는다.
5. SHORT 바스켓은 진입 bid·종료 ask의 비교 수익을 사용한다. 호가 스프레드가 이미
   반영되어 정적인 슬리피지를 중복 차감하지 않는다. 설치 시 비용은 편도 수수료 두 번과
   SHORT 추가비용 가정의 합을 고정한다. 현재 기본값은 22bp지만 실제 규약값이 우선이다.
   현재 fundingRate 필드는 원본 응답에 보존하되 실제 펀딩 현금흐름으로 정산하지 않는다.
6. 같은 가격·비용에서 모델 5개와 운영 선택 5개의 차이를 표시한다. 비실행 WATCH의
   가상 성적을 실제 거래 성과로 바꾸지 않으며, actionable 0건을 성공한 거래로 세지 않는다.

후속 [선정 경로·금액별 호가 잔량·확정 펀딩 이력](execution_diagnostics.md)은 별도 진단
규약으로 추가했다. 이 문서의 기존 고정 비용 성적표는 바꾸지 않으며, 공개 펀딩 정산율을
수집하더라도 실제 계좌의 펀딩 현금흐름으로 간주하지 않는다.

공식 필드·엔드포인트: [Bitget Classic Contract Market, Get All Tickers](https://www.bitget.com/docs/catalog/classic-contract-market/classic-contract-market).
읽기 전용 `GET /api/v2/mix/market/tickers?productType=USDT-FUTURES`만 사용하며 주문·인증키는 없다.
관찰 창과 신선도·비용은 이 프로젝트의 명시적 가정이며 업계에서 검증된 최적값이 아니다.

## 자동 운영과 복구

- 기존 `xsec-experiment-supervisor.timer`가 10분마다 원본 수집, 평가, 대조, 전송 확인,
  호가 관찰과 복원 검증을 실행한다. 별도 사용자 명령이나 터미널 상주는 필요 없다.
- `output/forecast_audit/ledger.sqlite`: 규약, 원본, 원시 가격, IC, 비교, 보고서,
  관찰 종목·비중, 호가 및 거래소 비교 결과. 내용 해시와 UPDATE/DELETE 차단을 적용했다.
  각 행에 기록 프로그램의 소스 해시와 numpy/pandas/scipy 버전을 보존한다.
- `output/forecast_audit/summary.json`: 현재 상태·누락·가격 대기·IC 차이·첫 실행 연결·호가 비교.
  상세 데이터는 암호화 대시보드에만 내보내며 공개 요약에는 포함하지 않는다.
- `output/forecast_audit_backups/`: 전체 증거를 포함한 SQLite hot backup을 해시로 보존하고,
  임시 위치로 복원해 가격·IC·비교·전송 연결·호가 산술을 다시 검사한다.
  동일 디스크 복구용이며 물리 디스크 고장은 보호하지 않는다.
- 운영 점검은 `FORECAST_AUDIT`, `FORECAST_BACKUP`, `VENUE_OBSERVATION`을 감시한다.
  IC 차이 자체는 진단 경고이지 서비스 장애가 아니다. 실험 감독의 다른 업무와 실패를 분리한다.

## 입력 장애 격리와 복구 이력

9월 30일 후속 검증에서 비교용 JSON·원본·보고서 손상, 가격 DB 접근 실패, 기존 IC의
종목 수·사이드 호환성 문제를 테스트로 재현했다. 실제 운영 원본이 손상됐다는 의미는 아니다.
종전에는 입력 하나의 오류가 같은 트랜잭션의 정상 채점·전송 확인까지 취소할 수 있었다.

- 신호 원본은 회차별로 검사한다. 그 회차 파일 중 하나라도 손상되면 일부 정상 파일만
  골라 평가하지 않는다. 해당 회차는 `source_error`로 남기고 다른 회차를 계속 처리한다.
- 가격 DB 장애 중에도 신호·보고서를 기록한다. 정상 가격이 평가 기한 안에 확보돼야
  채점하며, 오류가 있었다고 원래 +55h 기한을 연장하거나 만료 결과를 되돌리지 않는다.
- 기존 IC 파일과 재계산 원본의 오류는 원본 점수 채점을 막지 않는다. 재계산 원본만
  손상됐다면 확인 가능한 기존 IC 숫자는 별도로 비교한다. 다른 사이드·호라이즌은 제외한다.
- 기존 측정기가 허용하는 5~9종목 재계산 이력도 대조할 수 있다. 원본 채점의 최소
  10종목, 전체 종목 고정 기준은 그대로다. 서로 다른 종목군을 동일한 재현으로 표시하지 않는다.
- 보고서는 파일별로 검사한다. 불량 보고서 때문에 다른 정상 보고서의 수신 확인을
  취소하지 않는다. 잘못된 거래소 매핑은 거래소 관찰 실패로 남기고 정상 원본 채점은 유지한다.
- `ingestion_events`는 추가 전용 운영 이력이다. 입력 단계·대상·회차·확인 시각·오류와
  복구를 순서대로 기록하고, 같은 장애 반복은 중복 저장하지 않는다. 복구 후에도 실패를
  삭제하지 않는다. 이 기록은 실패 당시의 진단이지 손상 파일 원문 전체의 보관은 아니다.
- 기존 7개 증거 테이블·규약을 수정하지 않는 추가 테이블 방식이다. 이전 백업도 읽고
  검증할 수 있다. 새 백업은 운영 이력까지 포함하며 해시·사건 순서를 검사한다.
- 정상 채점과 별도로 미해결 입력 오류는 운영 경고다. +55h가 지나도 기존 IC가 없으면
  `missing`으로 표시하며 무기한 대기로 숨기지 않는다. 뒤늦은 비교 이력이 생겨도 원본
  평가의 만료·누락 결과는 바꾸지 않는다. 비교는 기술적 진단이며 원본 평가와 다르다.
- 입력 장애와 **원장·규약 무결성 실패는 다르다**. 후자는 기존처럼 즉시 중단하며
  성공 상태나 격리 가능한 외부 입력 오류로 취급하지 않는다.

```bash
python scripts/audit_forecasts.py --register  # 최초 미래 등록만
python scripts/audit_forecasts.py             # 독립 점검·복원 검증
python scripts/audit_forecasts.py --probe-quotes  # API 연결 점검; 실험 증거로 저장하지 않음
python -m pytest tests/test_forecast_audit.py tests/test_venue_observer.py -q
```

테스트와 API 연결 성공은 앞으로의 신호·호가·수익률이 실제로 확보됐다는 뜻이 아니다.
실제 첫 회차와 이후 성공·누락·실패는 자동 기록으로 확인한다. 이 시스템이 대화 종료 후
새 전략을 자율적으로 설계하거나 모델을 자동 승격시키지는 않는다.

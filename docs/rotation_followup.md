## 질문과 비교 대상

질문은 "국면별로 반전 기준선의 비중을 조금 허용하면, 항상 현재 모델만 사용하는
것보다 같은 미래 구간에서 나은가"다. [기존 60회 분석](completed_trial_analysis.md)은
가설을 만들기 위한 개발 자료로만 쓴다. 해당 60회를 새 파일럿의 학습·평가에 편입하지 않는다.

- 비교군: 해당 회차의 현재 모델 bottom-five, 동일 비중, 버퍼·게이트 없는 연구용 바스켓.
- 후보군: 기본은 비교군과 동일. 자격을 갖춘 국면에 한해 모델 75% + 반전 bottom-five 25%.
- 겹치는 종목은 비중 합산. 최대 10개 이름이 있는 **연구용 혼합**이며 실제 추천 5개
  계약과 다르다. 텔레그램 추천·LONG 차단·주문 API 없음은 그대로 유지한다.
- 두 군은 같은 시점·같은 관측 가능 종목군·같은 가격·비용 조건을 쓴다.
- 주간 재학습을 허용하는 현재 시스템의 비교다. 모델 해시를 매번 남기고
  고정된 단일 모델의 성능이라고 부르지 않는다.

## 결정 규칙

`utils/rotation_research.py`에 다음 규칙을 구현했다. 임계값 최적화나 조합 검색은 하지 않았다.

1. 월요일 00:00 UTC마다 그 시각 **이전에 평가까지 끝난** 최근 90일 기록만 사용한다.
   신호 당시 국면과 모델 해시가 있고, 45분 이내에 저장된 관찰만 허용한다.
2. 상승/하락 × 고/저변동 네 국면을 각각 처리한다. 라벨은 기존 국면 관찰 계약을 따른다.
3. 국면당 최소 30회·8개 UTC 날짜가 있어야 비교한다. 이는 정책 작동 최소 자료이지
   통계적 유의성 기준이 아니다.
4. 현재 선택보다 다른 방식의 평균이 0.25%p 이상 좋을 때 변경 후보로 잡는다.
   모델에서 반전으로 갈 때는 `model - reversal <= -0.25`, 복귀는 `>= +0.25`다.
5. **연속된 두 번의 서로 다른 주간 검토**에서 같은 변경이 요구되어야 한다.
   동일 주간 재실행은 중복 확인이 아니며, 한 주가 빠지면 확인 횟수가 초기화된다.
6. 변경 이후 14일 동안 같은 국면의 선택을 다시 뒤집지 않는다. 확인 조건을 만족해도
   냉각 기간이 남으면 보류한다.
7. 국면 미상, 표본 부족, 최신 주간 검토 부재/7일 경과 시 해당 신호는 모델 100%로 복귀한다.
   안전한 기본값 적용은 일반 변경 자격과 별개다.
8. 한 주 동안 국면별 선택표는 고정되지만, 각 신호가 속한 국면은 바뀔 수 있다.
   따라서 **주간 선택표 변경뿐 아니라 회차 간 실제 반전 비중 변화 모두**에 추가 비용을 붙인다.

30회, 8일, 0.25%p, 2주, 25%는 제한적인 후보 규칙이다. 업계 표준이나 최적값이라는
주장은 하지 않는다. 여러 대안을 돌린 뒤 가장 잘 나온 값을 채택하지 않았다.

## 성과와 비용

- 진입: 신호 다음 정시 원시 Upbit 시가. 종료: 진입 +6시간. 실제 Bitget 체결 성과 아님.
- 평가: 종료 봉 완료 이후. 모든 고정 종목 가격이 필요하며 결측·중복 가격은 채우지 않는다.
- 기본 비용: 국면 원장에 등록된 동일 비용을 두 바스켓에 적용한다.
- 후보 비용: `abs(이번 반전 비중 - 이전 반전 비중) * 10bp`를 추가 차감한다.
  이는 보수적인 별도 가정이며 실제 호가·체결 기반 turnover 모델이 아니다.
- 추가 비용 0/10/20bp 결과를 함께 보여주되 10bp를 기본값으로 고정하고 유리한 것을 고르지 않는다.
- 단일 주요 지표: 각 회차 `후보 net - 비교군 net`의 평균. 전체 평균과 절대 손실을 함께 표시한다.
- 미평가/누락 회차를 0% 수익이나 비교군과 동일한 수익으로 채우지 않는다.

## 기간과 종료

고정 **336개 예정 회차 = 84일**의 실행 가능성 파일럿을 등록했다. 목적은 전환 정책이
실제로 작동하는 빈도, 관찰 범위, 추가 비용, 새로운 차이값의 분산을 측정하는 것이다.
**84일이면 우위가 증명된다는 의미가 아니다.** 기존 모델-반전의 검정력 계산을
25% 혼합 후보-모델이라는 다른 지표에 그대로 적용하지 않는다.

시작은 별도 등록 이후 미래 슬롯으로 고정한다. 등록 시 336개 회차와 첫/마지막 시각,
최종 처리 기한을 규약에 저장하며 재등록·덮어쓰기를 거부한다.
마지막 신호의 +7h 종료 시점과 추가 48h 가격 유예까지를 최종 처리 기한으로 둔다.

| 종료 조건 | 기록할 결론 |
| --- | --- |
| 무결성 실패 | 성과 해석 불가 |
| 누락·가격 오류로 336쌍 미완결 | 자료 부족, 실패·누락 내역 보존 |
| 후보 비중 >0인 회차가 30 미만 또는 8 UTC 날짜 미만 | 정책 작동 자료 부족 |
| 나머지 | 파일럿 완료, 수익 우위 확정 아님 |

좋은 숫자가 나올 때까지 연장하지 않는다. 평균 차이가 음수여도 그대로 보고하고,
특정 국면의 양수만 뽑아 성공이라 부르지 않는다. 이후 확증 실험은 이 새로운 지표의
분산과 실용적 개선 폭으로 표본을 다시 설계하고, 별도 미래 자료로 시작한다.

## 자동 실행 경로

`utils/rotation_pilot.py`와 `scripts/rotation_pilot.py`가 실행 경로다.
이미 운영 중인 `xsec-experiment-supervisor.timer`가 10분마다 국면 관찰을 정산한 뒤
파일럿을 처리한다. 추천 프로그램의 모델·점수·Telegram 경로는 수정하지 않았다.

- `output/rotation_pilot/ledger.sqlite`: 규약, 주간 결정, 비중 관찰, 성과, 최종 판정.
  행별 체크섬 및 SQL UPDATE/DELETE 차단. 사용한 원본 예측·가격 결과도 함께 보존한다.
- 신호 +45분 이내, 다음 정시 진입 전에 비중을 저장한다. 원본 관찰이 늦거나
  점검 프로그램이 놓친 회차는 `missed`로 남기며 소급 결정하지 않는다.
- 원본 결과의 종목 구성·원시 수익률·비용을 다시 검산한 뒤 파일럿의 저장된 비중과
  비중 변경 비용을 적용한다. 원본 결과가 +55h까지 없으면 `missing_source_outcome`.
- 직전 **예정 회차**가 누락됐다면 이전 비중은 0으로 가정한다. 실제 거래가 있었다고
  가정하지 않으며 해당 파일럿은 완결 자료가 아니므로 `insufficient_evidence`로 종료한다.
- 주간 결정에는 당시 사용한 원본 예측·성과를 복사해 미래 데이터와 분리한다.
  지나간 주간 결정을 사후 생성하지 않는다. 첫 등록 주에는 기본 모델 비중을 사용한다.
- 정상 종료는 원장 `terminal`과 `final_review.json`에 고정된다. 무결성 위반은 별도의
  `integrity_failure.json`에 고정하고 자동 재개하지 않는다. 일시적인 I/O 장애는 재시도한다.
- `output/rotation_backups/`: 원장·규약·결정 코드·완료/실패 보고서의 동일 디스크 사본.
  SQLite hot backup, 해시·산술 검증과 임시 복원을 수행한다. 별도 디스크는 요구하지 않는다.
- 운영 점검은 `ROTATION_PILOT`, `ROTATION_BACKUP` 신선도·성공 여부를 검사한다.
  기존 장애 알림 경로를 사용하고, 새 투자 추천 메시지는 만들지 않는다.

기존 관찰 원장에서 나중에 선택 비중을 계산해 넣는 것은 prospective 예측이 아니다.
그런 소급 기록을 만들지 않는다. 앞서 생성된 `trial_diagnostics/followup_plan.json`의
`designed_not_registered`는 **당시 설계 기록**으로 보존한다. 실제 가동 상태는
새 `rotation_pilot/summary.json`으로 표시해 두 기록을 혼동하지 않는다.

등록 이후 다음 소스는 파일럿 계약에 고정되므로 수정 후 해시만 바꿔 이어가지 않는다:
`utils/rotation_pilot.py`, `utils/rotation_research.py`, `utils/prospective.py`,
`utils/regime_observer.py`, `utils/eval_metrics.py`, `scripts/rotation_pilot.py`.
평가에 쓰는 numpy/pandas/scipy 버전도 고정한다. 계약 변경은 별도 검토된 새 실험이 필요하다.

## 근거와 재현

시장 국면 가설의 참고 문헌은 [Ang·Timmermann](https://www.nber.org/papers/w17182),
표본 계산의 근거는 [NIST](https://www.itl.nist.gov/div898/handbook/prc/section2/prc222.htm)다.
후보의 임계값은 문헌에서 검증된 수치가 아니라 이 프로젝트의 명시적인 연구 가정이다.

```bash
python scripts/analyze_completed_trial.py
python scripts/rotation_pilot.py --register  # 최초 미래 등록만; 기존 원장 재설정 불가
python scripts/rotation_pilot.py             # 캡처/정산/복원 점검, Telegram 전송 없음
python -m pytest tests/test_rotation_research.py tests/test_rotation_pilot.py -q
```

테스트는 미래/늦게 평가된 결과 차단, 주간 중복·역행·누락, 냉각 기간,
미상·표본 부족·오래된 검토의 기본값, 매 비중 변화 비용을 검증한다.
336회 합성 원장 전체 종료, 누락·정산 오류·원본 변조·코드 변경·보고서 보존·실제
복원도 테스트한다. 테스트 자료는 별도 임시 디렉터리에만 쓰며 실제 원장에 편입하지 않는다.
소프트웨어 테스트가 통과해도 전략의 수익성이 입증되는 것은 아니다.

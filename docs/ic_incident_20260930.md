# 2026-09-30 SHORT FREEZE 진단

## 결론

**동결은 유지한다.** 당시 저장된 예측과 원시 가격으로 평가해도 두 회차 모두
순위 IC가 음수다. 측정 경로에는 별도의 재현성 문제가 있으나, 이번 동결을
단순한 측정 오류라고 처리하거나 게이트를 완화할 근거는 없다.

직전 모델로 되돌리는 것, Binance 미상장 종목을 제외하는 것, 특정 국면을 차단하는 것
중 어느 것도 이번 두 회차만으로 정당화되지 않는다. 아래는 실패 원인을 좁히는
사후 진단이며 새로운 전략의 성능 검증이 아니다.

## 가설별 판정

### 가격 누락 때문에 잘못 동결됐는가

대상 두 회차에서는 지지되지 않는다. 원시 가격 200쌍이 모두 유효하고 저장 점수의 IC도 음수다.
다만 이전 28일의 112개 예정 비교 중 40개는 전체 종목의 정확한 가격 쌍이 부족했다.
아래 과거 요약은 완결된 72개만의 기술 통계이며 결측 선택 편향이 가능하다.
40개를 0%로 채우거나 숨기지 않았고, 기존 IC 이력을 다시 쓰지도 않았다.

### 재학습으로 모델이 나빠졌는가

현재 모델 해시는 두 신호에 저장된 모델 해시와 같다.
직전 모델은 `models/archive/release_2026-09-27T200257/0_xsec_6h.pkl`이다.
**같은 평가 시점 제한·같은 종목·같은 입력**에서 이전 모델의 IC는
-0.113941 / -0.062488이다. 현재 모델은 -0.103992 / -0.076173이다.
한 회차는 새 모델이 조금 낫고 다른 회차는 조금 나쁘다. 이전 모델도 둘 다 음수이므로
이번 재학습을 단독 원인으로 단정하거나 즉시 롤백하지 않는다.

### 시장 방향 또는 종목 교체 탓인가

첫 회차는 전체 시장이 하락했는데 선택 SHORT 바스켓은 손실이었다.
한 종목의 +22.9545% 상승이 원래 20% 비중 기준 -4.6509%p를 기여했다.
다른 네 종목의 합은 +2.6184%p다. 이는 손실 집중도 설명이지 그 종목을 사후 제외한 전략이 아니다.
둘째 회차는 선택 5개 중 4개가 상승했고, 손실이 한 종목에만 집중된 경우와 다르다.

직전 회차에도 있었던 공통 종목만 보면 IC는 -0.055391 / -0.155308이다.
새로 편입된 종목만의 문제라는 설명도 지지되지 않는다. 부분집합 IC는 전체 IC의
가산 분해가 아니므로 두 값의 차이를 순수한 종목 교체 효과라고 부르지 않는다.

### 특정 국면 또는 팩터가 원인인가

현재 DB에서 직전 완료 BTC 봉만으로 재구성하면 둘 다 `bear_lowvol`이다.
완결된 과거 비교 중 같은 국면 26회의 평균 저장 IC는 +0.072376이다.
그러나 국면 라벨은 당시 저장된 것이 아니고, 시간·모델 버전·누락이 섞였으므로
해당 국면이 항상 좋거나 나쁘다는 결론은 내리지 않는다.

현재 데이터로 재구성한 `reversal_4h`의 팩터 IC는 직전 7일 28개 회차 평균 +0.07619에서
대상 두 회차 -0.06984 / -0.14140으로 바뀌었다. 반전 성향의 실패를 의심할 근거지만,
원래 신호 입력의 완전한 원본이 없어 확정적인 원인 기여율은 계산할 수 없다.
팩터 하나를 0으로 바꾸는 민감도 결과도 보고서에 남기되, 이를 학습된 대체 전략으로 취급하지 않는다.

교차거래소 입력 결측은 현재 재구성 기준 27개 / 22개다. 둘째 회차 결측 그룹 IC는
-0.33936, 완전 입력 그룹은 +0.01481이지만 서로 다른 종목 집합이다.
결측을 제거하면 성능이 좋아진다는 인과 증거가 아니므로 사후 필터를 배포하지 않는다.

## 확인된 측정 구조 문제

`scripts/track_ic.py`는 저장 예측을 읽지 않고, 실행 당시 모델·DB·45일 로더로
과거 점수를 다시 만든다. `data/features.py`의 `load_and_pivot()`는 전방 채움 후
로드 구간 전체에서 결측이 없는 종목만 남긴다. **시작 행의 결측 여부**가 전체
포함 여부를 바꾸며, 크로스섹션 정규화는 상위 100개 필터 전에 수행된다.

실제 로그의 완전 데이터 종목 수는 신호 시점 266 / 228개, 평가 시점 265 / 266개다.
진단 코드에서 역사적 조회 상한을 각각 신호 +12h로 고정하니 이 숫자와 기존 IC 두 값이
반올림 오차 0.0000005 이내로 재현됐다. 같은 첫 회차를 더 늦은 조회 상한으로 다시 계산하면
IC가 -0.058387로 달라진다. 따라서 기존 이력을 불변의 당시 예측 성적표라고 부르면 안 된다.

또한 조회 상한을 신호 시점으로 맞춰도 저장 점수와 완전히 일치하지 않는다.
현재 DB를 과거 시점에서 잘라 읽는 것과 당시 실제로 존재했던 원시 데이터 사본은 다르다.
원래 피처·데이터 개정 이력이 없어 이 차이 전체를 한 가지 원인으로 귀속하지 않는다.

## 적용한 보강

`utils/score_evidence.py`를 두 실행 경로에 연결했다.

- 신호 생성: SHORT 원래 입력의 NaN, 반올림 전 점수, 모델·소스 해시, 실제 기록 시각을 저장한다.
- IC 측정: 그 평가 때 재구성된 입력·점수·타겟을 별도로 저장한다. 기존 타겟이
  전방 채움 로더 기반임을 표시하며 원시 가격 검증 자료라고 부르지 않는다.
- 저장 위치는 `output/score_evidence/{signal,measurement}/`다. 내용 해시별 불변 문서로
  재실행본을 보존하며, 늦은 신호는 늦었다고 표시하고 당시 자료로 소급 주장하지 않는다.
- 기록 실패는 로그에 남기며 기존 추천·IC 계산·Telegram 전달을 막지 않는다.
- 실제 `python scripts/track_ic.py --side short` 실행으로 100개 평가 원본을 저장했다.
  실행 전후 IC 이력·게이트 상태·6h/12h 모델·원래 동결 모델 해시가 모두 같다.
- 첫 실시간 신호 원본은 설치 후 다음 정기 실행부터다. 과거 신호 원본을 만든 것처럼
  저장하지 않았다. 새 국면 관찰·336회 파일럿·기존 60회 실험 규약과 판정도 그대로다.

이 보강은 진단 가능성을 높이는 것이지 수익률 개선을 주장하는 모델 변경이 아니다.
확인된 부진과 재현성 한계를 함께 기록하며, 현재 `FREEZE` 및 비실행 참고 후보 전달을 유지한다.

## 재현

```bash
python scripts/diagnose_ic.py
python -m pytest tests/test_ic_incident.py tests/test_score_evidence.py -q
python scripts/verify_telegram.py --recent 50
```

`diagnose_ic.py`는 가격·모델 읽기 락을 잡고 원본 입력 해시가 실행 중 변하지 않았는지도 검사한다.
실행 시점에 모델이나 최근 두 저조 회차가 달라지면 이번 사건의 완전한 재현과 구분해야 한다.
보고서는 생성 시각·입력·소스 해시를 포함한 새 문서로 남고 기존 문서는 보존된다.

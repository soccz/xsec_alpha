# 추천 선정 경로와 금액별 거래소 관찰

2026-09-30. [자동 성적표](forecast_audit.md)에 남아 있던 선정 과정과 비용의 관찰 공백을
보강한다. 기존 22bp 호가 성적, 등록 실험, 모델과 안전 게이트는 그대로다. 주문 API는 없다.

## 추천 선정 경로

정상 보고서에 당시 전체 점수, 거래 대상 목록과 순서, 이전 SHORT/LONG 추천 목록,
추천 수 제한, 버퍼 폭, 저장 직전 선정 종목, 저장 전 품질 정보를 함께 기록한다.
기존 선정 함수를 읽기 전용으로 재실행해 실제 선정 목록과 비교하고, 보고서에 실린
목록과도 대조한다. 소비자는 이를 원본 점수 해시와 연결해 다시 검사한다.

- 전체 순위 → 거래가능 종목 순위 → 버퍼 선정 → 최종 실행 가능 여부를 구별한다.
- 이전 추천은 실제 보유 포지션이 아니다. 유지됐다는 이유로 거래했다고 세지 않는다.
- 게이트가 차단돼도 모델 후보와 버퍼 참고 목록은 기록하되 실행 0건은 그대로 둔다.
- 동점 순서와 버퍼 효과를 혼동하지 않는다. 순위는 동점 최저 순위를 함께 표시한다.
- 선정 재현이나 보고서 일치가 실패하면 운영 점검에서 표시한다. 설명 기록 실패로
  필수 Telegram 보고를 중단하지 않는다. 원장과 대시보드에는 그 실패 상태를 남긴다.
- 이 경로는 선택 규칙의 설명이다. 팩터의 인과 설명이나 게이트 효과의 확증 실험이 아니다.

## 금액별 호가 잔량

별도 `depth_funding_diagnostics_v1` 규약을 **다음 미래 신호부터** 등록한다.
원본 감사 규약을 바꾸지 않고, 같은 원장 안 `execution_details`에 규약과 증거를 추가한다.

실제 등록은 **2026-09-30 17:43:32 KST**, 첫 신호는 **20:00 KST**다.
규약 SHA-256은 `1bd7f829932339e28b5771d0864c121036cb83e4004b35230108e8514cc0968e`,
최초 복원 checkpoint는 `e04fe40f545965e0eb2330d6c5b48161ac192e5bc576227a0f3a2318f4884d58`다.
등록 시 실제 호가·펀딩 관찰은 0건이며, 연결 점검 자료는 편입하지 않았다.

1. 기존 진입 전 고정한 모델 5개·선정 5개의 합집합만 관찰한다. 결과를 본 뒤 종목을 바꾸지 않는다.
2. 진입·종료 정시부터 300초 안의 첫 관찰을 저장한다. 비합산 `scale0`, 50단계 호가를
   사용하며 양수 가격·수량, 정렬, 중복, 역전, 거래소 시각을 검사한다. 시세 나이는
   -5~60초만 허용한다. 잘못된 호가를 정렬·보간해 정상 자료로 바꾸지 않는다.
3. 코인별 명목금액 **100·500·1,000 USDT**를 미리 고정한다. 수량은 명목금액/진입 최우선 bid다.
   이 수량을 진입 bids에서 매도하고 종료 asks에서 그대로 매수하는 가상 호가 계산을 한다.
   매수·매도 대금으로 수익률을 계산하고 등록된 고정 수수료·추가비용을 차감한다.
4. 50단계 잔량이 부족하면 계산 불가다. 마지막 가격으로 나머지를 체결했다고 가정하지 않는다.
   5종목 중 하나가 불완전해도 나머지 종목으로 평균을 재계산하지 않는다.
5. 같은 호가에서 최우선 가격만 쓴 결과와 잔량을 사용한 결과 차이를 별도로 저장한다.
   스프레드를 이미 포함한 계산에 정적 슬리피지를 다시 빼지 않는다.

이는 동시 체결·잔량 유지·최소 주문 단위·계좌별 수수료·시장 충격·지연을 증명하지 않는다.
5개 코인의 비교 수익률 평균이며 실제 계좌 손익이나 투자금 권고가 아니다.

## 확정 펀딩 이력

현재 예상 fundingRate가 아닌 공개 과거 정산율을 읽는다. 종료 기준 9시간과 관찰 창이
지난 뒤 첫 점검에서 조회하고, 실제 종료 관찰 시각 +36시간이 지나면 누락으로 남긴다.
조회는 최근 100건 한 페이지이며 양 끝 관찰 시각을 둘러싼 이력이 있어야 한다.
중복, 다른 심볼, 비유한 값, 미래 정산, 관련 구간의 8시간 초과 공백은 실패다.
이 검사는 반환 자료의 일관성 점검이지 거래소 이력의 독립적인 완전성 보증은 아니다.

- 관찰된 진입 시각보다 뒤이고 종료 시각 이하인 정산율을 합산한다.
- SHORT 기준 양수는 수취 방향, 음수는 지급 방향이다.
- 진입·종료가 정산 시각 ±60초 안이면 적용 여부를 확정하지 않고 `boundary_uncertain`으로 남긴다.
- 이력이 없다고 펀딩 0으로 채우지 않는다. 양 끝 이력으로 둘러싸인 구간에 정산이 없을 때만
  반환 자료 기준 합계 0이다. 정산 간격이 바뀔 수 있으므로 고정 8시간 지급을 생성하지 않는다.
- 실제 펀딩 현금흐름은 정산 당시 마크 가격과 보유 수량이 필요하다. 현재 합계는 고정
  명목금액의 정산율 비교치다. **호가 비교 손익에 더하지 않으며 실제 펀딩 정산으로 표기하지 않는다.**

출처: [Bitget 공개 호가·펀딩 API](https://www.bitget.com/docs/catalog/classic-contract-market/classic-contract-market),
[Bitget 펀딩 산식·정산 시점 설명](https://www.bitget.com/academy/funding-rates-calculation-in-futures-trading).
관찰 금액·기한·허용 오차는 이 프로젝트의 사전 고정 가정이며 검증된 최적값이 아니다.

## 자동 운영과 실패 보존

기존 10분 감독 서비스에서 수행한다. 요청별 3초 timeout, 전체 추가 수집 90초 한도를
두고 첫 실패도 고정 기록한다. 더 유리한 호가로 재시도하지 않는다. API 실패·기한 초과·
잔량 부족·정산 경계는 상태와 이유를 보존하고 기존 원본 채점과 Telegram 경로를 변경하지 않는다.
최근 관찰 장애는 운영 점검에서 알리되 지난 실패 기록은 회복 후에도 남긴다.
정상 JSON 응답을 받았지만 검증에서 탈락한 경우에는 응답도 보존해 같은 거절 이유가
재현되는지 검사한다. 비유한 값 등 저장 불가능한 응답은 실패 사유만 기록하며 정상 원본을 취소하지 않는다.

SQLite 추가 전용 테이블의 원본 응답과 산술을 백업 복원 때 다시 검사한다. 기존 백업도
계속 읽을 수 있고 신규 규약 재등록·초기화는 거절한다. 상세 정보는 암호화 대시보드에만
내보낸다. 공개 개발일지는 왜 보강했고 무엇이 아직 증명되지 않았는지를 설명한다.

```bash
python scripts/audit_execution.py --probe     # 실제 공개 API 점검, 원장에 넣지 않음
python scripts/audit_execution.py --register  # 최초 미래 등록만
python scripts/audit_execution.py             # 자동 관찰과 동일 경로 + 복원 검증
python -m pytest tests/test_execution_audit.py tests/test_selection_trace.py -q
```

## 검증 범위

금액·펀딩·선정 기록이 생겼다는 사실과 투자 우위는 다르다. 등록 전 자료를 실시간 관찰로
소급 편입하지 않는다. 실제 체결·계좌 펀딩·마크 가격·시장 충격과 수익 우위는 미검증이다.
현재 고정 실험과 국면 전환 파일럿을 그대로 유지하며, 이 진단 결과만으로 모델을
재학습하거나 후보 선정·안전 게이트를 자동 변경하지 않는다.
